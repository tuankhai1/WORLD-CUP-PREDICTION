# 2026 FIFA World Cup Prediction Model

Machine learning and Monte Carlo pipeline for forecasting the 2026 FIFA World Cup.

The project trains a stacked tabular ensemble on modern international results, adds team and squad-form features, simulates the tournament, and writes a self-contained HTML dashboard with:

- tournament winner probabilities
- an interactive two-team matchup selector
- projected group advancement
- a deterministic bracketology road to the final
- club-form power rankings
- model training metrics

## Current Status

This repo is ready to push without committing raw data, model artifacts, logs, or generated dashboards. Those paths are ignored by `.gitignore`.

Important modeling caveat: the dashboard bracket is currently "bracketology", not an official FIFA bracket implementation. It seeds a projected knockout path from group expected points and direct matchup probabilities. The simulator also uses an approximate knockout seeding model. When FIFA's official third-place assignment table is finalized, the bracket mapping should be implemented in both the Python and C++ simulators.

## Why Australia Looked Too High

Australia previously appeared in the top-five title probabilities. That was not simply saying Australia is a top-five squad on raw talent. It came from a combination of:

- strong modern/form Elo after recent international results
- strong recent form features: low goals conceded and good expected goal differential
- favorable direct model outputs against several teams
- path inflation from the simplified knockout bracket model

There was also a prediction-symmetry bug: because matchup vectors include absolute team features, `predict(A, B)` and `predict(B, A)` were not guaranteed to be complements. `MatchPredictor` now averages both ordered predictions so win/draw/loss probabilities are symmetric. After that fix, Australia falls out of the top five in the saved simulation.

The remaining lesson still matters: before treating the tournament ranking as production-grade, retrain after calibrating feature importance or adding stronger validation around FIFA rating and club-form power.

## Data Inputs

Raw and generated data are intentionally ignored by Git.

Required or useful local inputs:

- `data/raw/github_historical.parquet`: generated by `GithubDataLoader`
- `data/raw/wc2026_matches.parquet`: local 2026 fixture/result file used for live updates
- `data/raw/SquadLists-English.pdf`: official squad list PDF
- `data/raw/players_data-2025_2026.csv`: backward-compatible player-stat export
- `data/raw/player_stats/*.csv`: optional extra league exports beyond the Top 5 leagues
- `data/raw/squad_players.csv`: optional normalized roster table for true roster-aware player matching

For non-Top-5 player coverage, put one CSV per league/provider in `data/raw/player_stats/`. The loader normalizes common column aliases such as `Goals`, `Assists`, `Club`, `Team`, `League`, and `Nationality`.

## Pipeline

1. `GithubDataLoader` fetches modern international results from `martj42/international_results`.
2. `DataMerger` combines historical results with `data/raw/wc2026_matches.parquet`.
3. `PlayerStatsLoader` builds `club_form_power` from squad/player stats.
4. `FeaturePipeline` builds team features and matchup vectors.
5. Optuna tunes CatBoost, XGBoost, and LightGBM base models.
6. `StackedEnsemble` trains a calibrated meta-model.
7. `MatchPredictor` generates all pairwise W/D/L probabilities.
8. `TournamentSimulator` runs Monte Carlo tournament simulations.
9. `DashboardGenerator` writes the HTML dashboard.

## Feature And Time-Weighting Formulas

### Elo expected result

Implemented in `src/features/elo_rating.py`.

```text
E_A = 1 / (1 + 10 ^ (-(R_A + H - R_B) / 400))
```

Where:

- `R_A`, `R_B` are current Elo ratings
- `H` is home advantage when applicable
- neutral World Cup matches use no home advantage

### Elo update

```text
R_A_new = R_A + K * MOV * (S_A - E_A)
R_B_new = R_B - K * MOV * (S_A - E_A)
```

Where:

- `S_A` is actual result: win `1.0`, draw `0.5`, loss `0.0`
- `K` depends on match type in `ELO_K_FACTORS`
- `MOV` is the margin-of-victory multiplier

### Margin-of-victory multiplier

```text
MOV = ln(min(abs(goal_diff), ELO_MOV_CAP) + 1) + 1
```

Current cap:

```text
ELO_MOV_CAP = 3
```

### Elo time decay

Ratings decay back toward the neutral baseline after inactivity.

```text
R_decayed = baseline + (R_previous - baseline) * exp(-ln(2) * elapsed_days / half_life_days)
```

Current values:

```text
baseline = 1500
ELO_HALF_LIFE_DAYS = 1095
FORM_ELO_HALF_LIFE_DAYS = 180
FORM_ELO_K_MULTIPLIER = 3.0
```

The model therefore keeps a slower long-term Elo and a faster form Elo.

### Training sample recency weight

Implemented in `src/features/pipeline.py`.

```text
recency_weight = max(RECENCY_MIN_WEIGHT, 0.5 ^ (age_days / RECENCY_HALF_LIFE_DAYS))
sample_weight = recency_weight * match_importance_weight
```

Current values:

```text
TRAINING_CUTOFF_DATE = "2022-01-01"
RECENCY_HALF_LIFE_DAYS = 270
RECENCY_MIN_WEIGHT = 0.03
```

Match importance weights:

```text
world_cup = 1.50
qualifier = 1.25
continental = 1.15
friendly = 0.65
default = 1.00
```

### Finished-only rolling features

Rolling xG, pressing, and form features are built only from rows with completed scores. Upcoming fixtures can remain in the merged match table for simulation/result locking, but they are not used as historical form.

### Club form power

Implemented in `src/data_ingestion/player_stats_loader.py`.

Player form is position-aware:

- forwards: goals, assists, shots on target, plus/minus
- midfielders: assists, interceptions, tackles won, points per match
- defenders: tackles won, interceptions, points per match, plus/minus
- goalkeepers: saves, points per match, plus/minus per 90

The player score is multiplied by a minutes factor:

```text
minutes_factor = min(1.0, max(0.15, minutes / 900))
```

With a normalized roster file, squad form is:

```text
club_form_power = 0.65 * mean(top_11_player_form) + 0.35 * mean(depth_12_player_form)
```

Without a normalized roster file, the fallback groups players by nationality and sums the top 15 form scores.

## Dashboard Notes

The dashboard no longer lists every group fixture as a static table. Instead:

- use the matchup explorer to choose any two teams
- use the bracketology section for a projected road to the final
- use group cards and winner charts for tournament-level context

The bracketology view is deterministic and explanatory. The Monte Carlo winner probabilities are still the main probabilistic tournament output.
