# 2026 FIFA World Cup Prediction Model

Machine learning and Monte Carlo pipeline for forecasting the 2026 FIFA World Cup.

This project uses modern international football match results, team/squad form, and an advanced stacked tabular ensemble model to simulate the 2026 World Cup tournament. It produces a comprehensive HTML dashboard featuring tournament winner probabilities, an interactive matchup selector, projected group advancements, and deterministic bracketology.

## Project Architecture

The architecture of the prediction system is separated into five core layers:

1. **Data Ingestion Layer (`src/data_ingestion/`)**: Responsible for sourcing raw historical data from GitHub repositories, merging it with local 2026 fixture data, and aggregating detailed player and squad statistics to determine team power levels.
2. **Feature Engineering Layer (`src/features/`)**: Processes raw match results to create time-weighted historical form, Elo ratings, rolling expected goals (xG), pressing metrics, and positional club-form power. It outputs structured matchup vectors for training and inference.
3. **Modeling Layer (`src/model/`)**: Uses hyperparameter tuning (Optuna) across multiple base gradient boosting models (CatBoost, XGBoost, LightGBM). These base models are combined via a stacked ensemble meta-model to produce calibrated win/draw/loss probabilities and expected goal differentials for any given matchup.
4. **Simulation Engine (`src/simulation/`)**: Takes the probability matrix generated by the modeling layer and runs hundreds of thousands of Monte Carlo simulations of the entire World Cup tournament. It supports both a Python-based simulator and a highly optimized C++ engine (via pybind11) for massive scale.
5. **Presentation Layer (`src/output/`)**: Generates a standalone, interactive HTML dashboard visualizing the results of the Monte Carlo simulations, bracket paths, group phase outcomes, and training metrics.

## Detailed Pipeline Explanation

The entire prediction process is orchestrated sequentially via `main.py` using a structured pipeline.

### Phase 1: Data Gathering & Merging
1. **Historical Results Parsing (`GithubDataLoader`)**: Pulls comprehensive modern international match data from `martj42/international_results`, cleaning and normalizing the dataset.
2. **2026 Fixture Injection (`DataMerger`)**: Merges the historical dataset with the localized `wc2026_matches.parquet` file, ensuring upcoming fixtures and newly completed World Cup results are natively integrated.
3. **Squad Power Calculation (`PlayerStatsLoader`)**: Analyzes squad lists, aggregating player statistics (from Europe's top leagues and beyond) based on positional rules (e.g., goals/assists for forwards, interceptions for defenders). It calculates a `club_form_power` index for every nation.

### Phase 2: Feature Engineering
4. **Feature Vectorization (`FeaturePipeline`)**: Transforms the merged match data into training matrices. This includes:
   - Calculating dual Elo ratings (long-term Elo and fast-decay form Elo).
   - Computing rolling averages for goals, expected goals (xG), and pressing intensity.
   - Determining sample weights based on match importance (World Cup = highest weight, Friendlies = lowest) and recency decay.

### Phase 3: Model Training & Inference
5. **Hyperparameter Tuning (`Optuna`)**: Evaluates CatBoost, XGBoost, and LightGBM across dozens of trials to find the optimal parameters for the given feature matrix.
6. **Stacked Ensemble Strategy (`StackedEnsemble`)**: Trains the base models and feeds their outputs into a logistic regression/meta-model layer. This calibrates the final output to ensure the W/D/L probabilities accurately reflect real-world variance.
7. **Pairwise Probability Generation (`MatchPredictor`)**: Using the trained ensemble, the predictor computes symmetric W/D/L probabilities and expected goal differentials for every possible matchup in the tournament.

### Phase 4: Monte Carlo Simulation
8. **Tournament Execution (`TournamentSimulator`)**: Utilizes the generated probability matrix to simulate the World Cup bracket.
   - For incomplete matches, it randomly samples outcomes based on the predicted W/D/L distribution.
   - It calculates group standings, applies tie-breakers, and resolves the knockout bracket round-by-round.
   - This process is repeated 100,000+ times to establish the true statistical likelihood of each team advancing or winning the title.

### Phase 5: Dashboard Output
9. **Dashboard Rendering (`DashboardGenerator`)**: Compiles the simulation aggregates (winner %s, group placements) alongside the direct pairwise probabilities into a dynamic `dashboard.html` file, saving it into the `output/` directory.

## Setup & Installation

```bash
pip install -r requirements.txt
python setup.py build_ext --inplace
```

*Note: The C++ build via `setup.py` is optional but highly recommended for fast, large-scale Monte Carlo runs. Currently, if live match results need to be locked in mid-tournament, the pipeline falls back to the Python simulator.*

## Command Line Interface

The project is controlled via `main.py` with the following key commands:

```bash
# Full pipeline: ingest, feature engineer, train, simulate, and generate dashboard
python main.py --mode full --iterations 100000

# Faster training run (fewer tuning trials)
python main.py --mode quick --iterations 10000

# Update models and simulation with latest local match results
python main.py --mode update --iterations 100000

# Predict a specific matchup interactively in the terminal
python main.py --mode predict --teams Spain Brazil

# Re-run simulation only using saved models
python main.py --mode simulate --iterations 100000

# Rebuild dashboard HTML without re-running simulations
python main.py --mode dashboard
```

## Feature & Time-Weighting Formulas

### Elo Expected Result
```text
E_A = 1 / (1 + 10 ^ (-(R_A + H - R_B) / 400))
```
*Note: `H` is home advantage. Neutral World Cup matches use no home advantage.*

### Elo Update & Decay
```text
R_A_new = R_A + K * MOV * (S_A - E_A)
R_decayed = baseline + (R_previous - baseline) * exp(-ln(2) * elapsed_days / half_life_days)
```
Where `S_A` is the actual result (1.0 for win, 0.5 for draw), `K` is the match importance factor, and `MOV` is the margin-of-victory multiplier capped at a 3-goal difference. 
The system maintains both a long-term baseline Elo (1095 day half-life) and a short-term form Elo (180 day half-life).

### Training Sample Recency Weight
```text
recency_weight = max(0.03, 0.5 ^ (age_days / 270))
sample_weight = recency_weight * match_importance_weight
```

## Modeling Notes & Caveats

- **Bracketology vs Official FIFA Implementation:** The dashboard bracket is an explanatory "bracketology" path rather than an exact FIFA third-place knockout mapping. It seeds a projected knockout path from group expected points. Once the official third-place assignments are set, both the Python and C++ simulators should be updated.
- **Symmetry:** Matchup predictions are symmetric. Because matchup vectors include absolute team features, the model averages `predict(A, B)` and `predict(B, A)` complements to ensure robustness.

## Git Hygiene

By design, data, models, build artifacts, and output dashboards are ignored by git to keep the repository lightweight. Before committing code, ensure no generated outputs (`*.pyd`, `*.log`, `output/`) are tracked.
